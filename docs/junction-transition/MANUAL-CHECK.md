## 1. 2台の Mac（同じ LAN）

- [ ] ホスト A・ゲスト B で手動接続。B を最初の DJ にして開始し、B の信号が STANDBY → READY になる。
- [ ] B がフェーダーを上げた瞬間に ON AIR になり、会場（Program 出力先）で音が途切れない・二重にならない。
- [ ] A が STANDBY で B の音を J に受け、CUE（ヘッドホン）とブースモニター（ローカル出力）の両方で聴ける。
- [ ] A がフェーダーを上げて ON AIR。B は OUTGOING になり、残りの曲のデッキはループ以外操作できず、ほかのデッキでは曲をロード・再生・CUE できる（会場には出ない）。
- [ ] A が J を下げ切ると 1.5 秒で解放され、B のロックが外れる。
- [ ] 残りの曲が終わる（または B が止めていないのに曲末に達する）と約 3 秒で自動解放される。
- [ ] READY 前にフェーダーを上げていた DJ に「一度フェーダーを下げてください」が出て、下げてから上げると ON AIR になる。
- [ ] READY でない状態でフェーダーを上げると「まだ本番に出ていません：理由」が表示され、会場に出ない。
- [ ] ON AIR の DJ の画面に次の DJ の準備状況（受信中／ロード済み／CUE中／READY）が出る。
- [ ] 合図（あと1曲・次どうぞ・少し待って・OK）が相手の画面に出る。
- [ ] ホストの強制交代・スキップ・強制解放、B2B の繰り返し、「順番に入る／外れる」、ドラッグでの順番変更。
- [ ] MASTER つまみを動かしても会場の音量が変わらない（ブースだけ変わる）。
- [ ] マイク ON が ON AIR の合図になる。OUTGOING 中のマイクは会場に出ない。
- [ ] 3 人（ゲスト→ゲスト）で、J がホスト経由で次の DJ に届き、交代が途切れない。

## 2. 別回線（インターネット越し・TURN）

- [ ] 異なる回線の 2 台で READY になる（「回線の遅延が大きく、会場の音に間に合いません」が出ないか、出る条件）。診断の「回線の遅延」の値を記録する。
- [ ] 持ち込み TURN 経由で同じ交代ができる。
- [ ] 回線が一時的に止まったとき（Wi‑Fi 切替、スリープ）の STANDBY／OUTGOING の振る舞いと復旧。
- [ ] ON AIR の DJ が切断したとき：自動交代の設定なら READY の次の DJ に交代する。確認設定なら復旧状態になり「このPCの演奏で再開」「次のDJに交代」が使える。
- [ ] OUTGOING の DJ が切断したとき、J が無音になり自動で解放される。次の DJ が切断したとき、順番が繰り上がりホストに理由が出る。

## 3. PlumDeck Lite（スマホ・ブラウザ）

- [ ] Lite ホスト＋Lite ゲスト、Mac ホスト＋Lite ゲスト、Lite ホスト＋Mac ゲスト の各組み合わせで、STANDBY → READY → ON AIR → OUTGOING → 解放 が一周する。
- [ ] Lite の DJ が ON AIR のとき、会場に前の DJ の残りの曲（J）が含まれる。
- [ ] Lite の OUTGOING で、残りの曲のデッキだけがロックされ、もう一方のデッキは使える。マイクは送られない。
- [ ] Lite が絡む交代は時刻で切り替えるため、前の DJ の音が一瞬重なる程度であること（重なりの長さを記録）。
- [ ] iOS Safari / Android Chrome で、J の CUE（MONITOR 出力）と送出が動く。画面ロック・バックグラウンド時の振る舞い。
- [ ] 旧バージョンの Lite / plumdeck と接続したとき「相手のアプリを更新してください」が出て、交代できない。

## 4. DDJ-1000

- [ ] MIDI 設定で「JUNCTION MASTERのチャンネル」を CH4（または CH3）にすると、J を受けている間だけそのチャンネルの LEVEL・EQ・CUE・クロスフェーダー割り当てが J を操作し、デッキ側は元のデッキを操作する。
- [ ] ソフトテイクオーバー：物理フェーダーと J の値がずれているとき、合わせるまで反映されない。
- [ ] OUTGOING 中、残りの曲のデッキとクロスフェーダーの操作が無視され、解放後に値のジャンプが起きない。
- [ ] フェーダーを上げる操作で ON AIR になる（MIDI 経由でも遅延なく反応する）。
